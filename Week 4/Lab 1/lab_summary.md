# lab_summary.md — LangGraph vs LangChain

LangChain agents (Lab 1) gave the complaint bureau a creative, freeform problem-solver: given a goal and a toolbox, the agent decides at runtime how to reach a solution, which tools to call, and in what order — making it excellent for exploratory, open-ended tasks where the right path is unknown in advance. LangGraph (Lab 2), by contrast, encodes the process itself as a first-class citizen: every stage (intake → validate → investigate → resolve → close) is an explicit node, every transition is a declared edge, and the shared `ComplaintState` TypedDict provides a full audit trail with no ambiguity about what happened or why. The trade-off is expressiveness vs. control — LangChain's agent can improvise a creative resolution the designer never anticipated, while LangGraph guarantees that no complaint ever skips validation or receives a resolution without documented evidence, which is exactly what compliance-sensitive systems require. Choose LangChain when the task is inherently open-ended and quality depends on creativity (drafting, brainstorming, multi-tool reasoning); choose LangGraph when the task demands traceable, consistent execution of a defined process — auditable pipelines, multi-step approvals, regulated workflows, or any scenario where "the agent did something unexpected" is a bug rather than a feature.
