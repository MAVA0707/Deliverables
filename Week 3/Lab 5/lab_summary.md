# lab_summary.md

MCP (Model Context Protocol) and direct API integration both enable agents to access external systems, but they serve different needs: MCP is the right choice when you're connecting to multiple services or want consistency across frameworks, because `MultiServerMCPClient` lets you register any number of servers in a single dict and immediately get LangChain-compatible tools — no per-service wrapper code, no inconsistent interfaces, and built-in observability via tool interceptors; direct API integration is the better fit when you have exactly one external service and need low-latency, full-surface access to its API, since adding the MCP abstraction layer introduces a small overhead and limits you to what the server chooses to expose. In practice, the decision comes down to scale and reuse: if today's one integration will grow into three next quarter, starting with MCP saves significant refactoring; if you're building a tight, performance-sensitive pipeline against a single known API, skip MCP and call it directly.
